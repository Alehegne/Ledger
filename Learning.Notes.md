# Spring boot configuration & depencencies Notes

- application.properties :- used to configure the application settings, such as database connection, server port, logging level, etc.with out hardcoding those settings in java classes.
  example:

```properties
spring.application.name=MyApp //used to set the name of the application, usefull in logging, monitoring, and other contexts where the application name is needed.
spring.datasource.url=jdbc:mysql://localhost:3306/mydb //used to set the URL of the database that the application will connect to.
spring.datasource.username=root //used to set the username for the database connection.
spring.datasource.password=secret //used to set the password for the database connection

spring.datasource.url=${DB_URL:jdbc:postgresql://localhost:5433/Ledger_DB} // the DB_URL environment variable is used to set the database URL, if it is not set, the default value jdbc:postgresql://localhost:5433/Ledger_DB will be used.
```

- JPA(java persistence API) :- is a specification for managing relational data in Java applications. It provides a standard way to map Java objects to database tables and perform CRUD operations on them. JPA is part of the Java EE (Enterprise Edition) platform, but it can also be used in standalone Java applications.
- Hibernate :- is an implementation of the JPA specification. It is a popular ORM (Object-Relational Mapping) framework that provides a set of tools and APIs for working with relational databases in Java applications. Hibernate allows developers to map Java objects to database tables, and it provides a powerful query language (HQL) for querying the database.
- properties for jpa and hibernate configuration in application.properties file

```properties
spring.jpa.hibernate.ddl-auto=none //used to set the Hibernate DDL (Data Definition Language) mode. In this case, it is set to "none", which means that Hibernate will not automatically create or update the database schema. flyway is used to manage database migrations and schema changes.
spring.jpa.show-sql=true //used to enable or disable the logging of SQL statements generated by Hibernate.
spring.jpa.properties.hibernate.format_sql=true //used to format the sql statements generated by hibernate, making them more readable in the logs.

ddl-auto(data definition language auto) property can have the following values:
- none: Hibernate will not perform any schema management. It assumes that the database schema is already created and will not make any changes to it.
- validate: Hibernate will validate the database schema against the entity mappings. If there are any discrepancies, it will throw an exception.
- update: Hibernate will attempt to update the database schema to match the entity mappings. It will create new tables, columns, and constraints as needed, but it will not remove any existing tables or columns.
- create: Hibernate will create the database schema based on the entity mappings. It will drop any existing tables and recreate them, which can result in data loss. This option is typically used in development or testing environments.
- create-drop: Hibernate will create the database schema based on the entity mappings, and then drop it when the session factory is closed. This option is typically used in testing environments where the database schema needs to be created and destroyed for each test run.
```

- spring-boot-starter-validation :- supports jakarta bean validation, which is a standard way to validate Java objects based on annotations. It provides a set of built-in validation constraints, such as @NotNull, @Size, @Email, etc., that can be used to validate the properties of Java objects. It also allows developers to create custom validation constraints if needed.

- spring-boot-starter-actuator:- provides production-ready features for monitoring and managing Spring Boot applications. It exposes various endpoints that can be used to monitor the health, metrics, and other aspects of the application. Some of the commonly used actuator endpoints include:
  - /actuator/health: provides information about the health of the application, including the status of various components such as the database, message broker, etc.
  - /actuator/metrics: provides metrics about the application, such as memory usage, CPU usage, request counts, etc.
  - /actuator/env: provides information about the environment variables and configuration properties used by the application.
  - /actuator/loggers: provides information about the logging configuration and allows changing the logging level at runtime.

- spring-boot-starter-flyway:- is a database migration tool that allows developers to manage database schema changes in a version-controlled manner. It provides a simple and reliable way to apply database migrations, which are scripts that modify the database schema or data. Flyway supports multiple database platforms, including MySQL, PostgreSQL, Oracle, SQL Server, and others. It can be integrated with Spring Boot applications using the spring-boot-starter-flyway dependency.
